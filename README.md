# Welcome

Welcome to the **Application Documentation** repo.

When you're writing, please follow the [Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/welcome/).

If you're using AI, please ensure you're only using our Enterprise Copilot option. **We can't have customer proprietary knowledge 
ending up in the world's general AI pool and being used to train it**. That's a non-negotiable, so please don't think you've come up with a special case for using one of the free ones.

If you're using AI to "assist" with your writing, tell it to **write in the style defined in the Microsoft Style Guide**.

When you're reading documentation here, you should struggle to determine who wrote it because we should all sound the same. If you want to see how that works,read any bit of Microsoft documentation.

## Your commitment

There's an onus on everyone creating/editing documentation to ensure it's of a high standard.

If you read documentation and it's wrong/outdated, **please fix it**. Don't leave it for some other poor soul to go through the same pain you've likely just
had to determine that document didn't help.

## Tooling

There's many ways to edit these documents and manage GitHub:

- All inside VS Code.
- Edit in VS Code and use GitHub's GUI tools.
- Edit in VS Code and use GitHub from the command line.
- Edit in your favourite ascii/text editor and use GitHub from the command line.

For the purposes of getting started and on the basis you have neither markdown nor GitHub experience, we'll show the steps for doing this all inside VS Code. As you get comfortable with process you might refine/speed up the way you do things. Equally, you may stick to VS Code permanently. There's no correct way and one way doesn't make you better than someone else. Many devs do all their source control from within Visual Studio/VS Code and never touch the command line. **In summary - whatever works best for you while maintaining the quality we're aiming for here.**
